## Problem & user

RocketShip PMs need this handled: Juno creates an evidence-backed brief from PM-selected RocketShip customer signals, with strategic and roadmap context for PM review.. Juno does this inside limits a human set on purpose, and defends every call it makes.

## 01 Context · Data Requirements

**Required sources, and exclusions**

Required: PM-selected items from RocketShip Raw Signals; the Product Strategy One-Pager; and the Product Roadmap. Raw Signals are the only evidence for customer claims. Strategy supports priority assessment. Roadmap supports a possible-match check against committed, planned, or uncommitted work. Excluded: unselected Raw Signals, Engineering Capacity Note, and Sales Pipeline Snapshot because they are not needed for an evidence brief.

**How fresh must it be**

Sources are read at request time. The brief reflects versions available when the PM starts the run. If a required source is unavailable, Juno produces a partial brief that names the unavailable source and makes no dependent claims.

## 02 Tools · System Capabilities

**The verb list**

read: retrieve only PM-selected Raw Signals, the Product Strategy One-Pager, and Product Roadmap. draft: extract source-linked claims, group signals, assess priority alignment, identify possible roadmap matches, and draft the evidence brief. write: none. send: none.

**Deliberate omissions**

No tools to search all customer data, edit Raw Signals, change the Product Roadmap, create tickets, update CRM records, or send messages. The brief is an input to PM judgment; these actions could create unsupported commitments or change systems of record.

## 03 Loop · AI Costs & Latency

**Turn ceiling and escalation**

One model pass per request is sufficient because Juno performs one bounded synthesis of three fixed sources: selected Raw Signals, strategy, and roadmap. A deterministic validation gate runs after the pass. Stop and return the brief for PM review if there are no selected signals, a source is unavailable, sources conflict, or a factual claim lacks a selected Raw Signal citation.

**Latency and cost target**

p95 under 8 seconds, with predictable cost per evidence brief. One model pass and three fixed read sources keep both latency and cost controlled.

## 04 Memory · Data Requirements

**What persists, at what scope**

Nothing persists beyond the active session. Selected signals, generated claims, and the draft brief are session-scoped and never cross users or teams.

**Expiry and write rules**

Session data expires when the session ends. No model output is saved as fact. A PM correction or edit always overrides generated content in the current session.

## 05 Permissions · AI Risks & Mitigations

**The permission tier**

| Side-effect class | Tier |
|---|---|
| read | auto |
| draft | auto |
| write | confirm |
| send | blocked |

**Justification**

Read is auto because sources are pre-scoped to selected signals plus two approved documents. Draft is auto because it is reversible and the PM reviews it. Write is confirm because any future write could alter a system of record; it is not implemented here. Send is blocked because Juno must not create external commitments.

## 06 Verification · AI Testing & Measurement

**The check before output ships**

Before display, verify: every customer claim cites selected Raw Signal IDs; no unselected signal appears; priority assessments map to the Product Strategy One-Pager; every roadmap match names the exact roadmap item and status; and assumptions, possible duplicates, and low-confidence conclusions are labeled. A deterministic validator checks these rules before rendering.

**Failure behaviour**

If validation fails, display the draft with failed sections marked Needs PM review and state the missing source, unsupported claim, or mismatch. Do not silently remove output or present an unverified claim as evidence.
